# 一覧の性能検証（2026-11-16）

## 対象と方法

- 指定された2フォルダの直下107件を使用。データの変更は行っていません。
- CPU使用量は対象プロセスのCPU時間差分を実測経過時間で割った、1コアを100%とする値です。タスクマネージャーの全コア合計表示とは異なります。
- 画面操作ツールを先に接続し、その後に対象アプリを起動して画面情報を取得する条件でも確認しました。
- 検索用のディスク列挙と、画面読み取り・選択変更・描画の負荷を分けて調査しました。

## 確認結果

旧ListViewでは、画面操作ツールの接続中に`WM_GETOBJECT`要求が毎秒数千回発生し、UIスレッドのCPU使用量が1コア換算約50～60%になるケースを確認しました。107件のディスク列挙は初回約16ms、再実行の中央値約4.8msで、今回の主要な負荷は列挙ではありませんでした。

v0.1.2では、一覧をDataGridViewへ変更して描画のダブルバッファリングを有効にしました。画面情報の取得後に待機させた4秒の測定ではCPU時間の増加が0秒でした。検索結果の値をアクセシビリティ経由で読み取れることと、絞り込み後に古い値が残らないことも自動テストで確認しています。

一方で、画面操作ツールの継続監視中には、キーリピートによる選択変更に伴って再取得の負荷が発生する場合があります。ツールのJavaScriptセッションを終了して接続を解放した後、下キーを押し続ける操作の引っかかりがなくなったことをユーザーが確認しました。検証終了時には監視接続を残さず終了します。

これは同一端末上の限定的な測定であり、すべての画面読み取りツールや負荷条件で同じ数値を保証するものではありません。試した起動設定だけの変更では通常版の負荷を解消できなかったため、追加の起動設定ファイルやランタイム切り替えは採用していません。

- 配布とインストール済みアプリの更新確認は、Release公開後に実施します。
